1 — ERD → Relational Table → DDL

Entity → Table • Attribute → Column • Identifier → Primary Key • Relationship → Foreign Key. Pada relasi 1:M, FK umumnya berada di sisi many. Relasi M:N membutuhkan associative table; pada SmartEdu peran itu dilakukan oleh ENROLLMENT.

2 — Tables & Creation Order

STUDENT, LECTURER, COURSE, SEMESTER → CLASS → ENROLLMENT.

Empat parent table pertama tidak saling bergantung. CLASS membutuhkan COURSE, LECTURER, SEMESTER. ENROLLMENT membutuhkan STUDENT dan CLASS.

3 — CHECK Before CREATE

SELECT table_name
FROM user_tables
WHERE table_name IN (
 'STUDENT','LECTURER','COURSE',
 'SEMESTER','CLASS','ENROLLMENT'
)
ORDER BY table_name;
Tidak ada object → CREATE. Sudah ada → jangan langsung DROP; periksa schema/struktur dan gunakan ALTER atau penyesuaian yang relevan.

4 — Oracle Data Types & Constraints

VARCHAR2 untuk teks/identifier; NUMBER untuk angka; DATE untuk tanggal. Gunakan PRIMARY KEY, FOREIGN KEY, NOT NULL, UNIQUE, dan CHECK untuk menerjemahkan business rules menjadi aturan database.

5 — Build SmartEdu: Full DDL

Step 1 — STUDENT

Sample business rule: untuk latihan ini, entry_year dibatasi 2020–2035. Angka ini adalah aturan contoh SmartEdu, bukan aturan SQL/Oracle.

CREATE TABLE STUDENT (
 student_id VARCHAR2(15),
 student_name VARCHAR2(100) NOT NULL,
 email VARCHAR2(100) NOT NULL,
 program VARCHAR2(100) NOT NULL,
 entry_year NUMBER(4) NOT NULL,
 CONSTRAINT pk_student PRIMARY KEY (student_id),
 CONSTRAINT uq_student_email UNIQUE (email),
 CONSTRAINT ck_student_entry_year CHECK (entry_year BETWEEN 2020 AND 2035)
);

Verify:

DESCRIBE STUDENT;
Step 2 — LECTURER
CREATE TABLE LECTURER (
 lecturer_id VARCHAR2(15),
 lecturer_name VARCHAR2(100) NOT NULL,
 email VARCHAR2(100) NOT NULL,
 CONSTRAINT pk_lecturer PRIMARY KEY (lecturer_id),
 CONSTRAINT uq_lecturer_email UNIQUE (email)
);
DESCRIBE LECTURER;
Step 3 — COURSE
CREATE TABLE COURSE (
 course_id VARCHAR2(15),
 course_name VARCHAR2(100) NOT NULL,
 credits NUMBER(1) NOT NULL,
 CONSTRAINT pk_course PRIMARY KEY (course_id),
 CONSTRAINT ck_course_credits CHECK (credits BETWEEN 1 AND 6)
);
DESCRIBE COURSE;
Step 4 — SEMESTER

ck_semester_dates memastikan tanggal akhir semester selalu sesudah tanggal mulai.

CREATE TABLE SEMESTER (
 semester_id VARCHAR2(15),
 academic_year VARCHAR2(9) NOT NULL,
 term VARCHAR2(10) NOT NULL,
 start_date DATE NOT NULL,
 end_date DATE NOT NULL,
 CONSTRAINT pk_semester PRIMARY KEY (semester_id),
 CONSTRAINT ck_semester_term CHECK (term IN ('ODD','EVEN')),
 CONSTRAINT ck_semester_dates CHECK (end_date > start_date)
);
DESCRIBE SEMESTER;
Step 5 — CLASS
CREATE TABLE CLASS (
 class_id VARCHAR2(15),
 course_id VARCHAR2(15) NOT NULL,
 lecturer_id VARCHAR2(15) NOT NULL,
 semester_id VARCHAR2(15) NOT NULL,
 class_name VARCHAR2(50) NOT NULL,
 capacity NUMBER(3) DEFAULT 30 NOT NULL,
 CONSTRAINT pk_class PRIMARY KEY (class_id),
 CONSTRAINT fk_class_course FOREIGN KEY (course_id) REFERENCES COURSE(course_id),
 CONSTRAINT fk_class_lecturer FOREIGN KEY (lecturer_id) REFERENCES LECTURER(lecturer_id),
 CONSTRAINT fk_class_semester FOREIGN KEY (semester_id) REFERENCES SEMESTER(semester_id),
 CONSTRAINT ck_class_capacity CHECK (capacity > 0)
);
DESCRIBE CLASS;
Step 6 — ENROLLMENT
CREATE TABLE ENROLLMENT (
 enrollment_id VARCHAR2(15),
 student_id VARCHAR2(15) NOT NULL,
 class_id VARCHAR2(15) NOT NULL,
 enrollment_date DATE DEFAULT SYSDATE NOT NULL,
 status VARCHAR2(15) DEFAULT 'ACTIVE' NOT NULL,
 CONSTRAINT pk_enrollment PRIMARY KEY (enrollment_id),
 CONSTRAINT fk_enrollment_student FOREIGN KEY (student_id) REFERENCES STUDENT(student_id),
 CONSTRAINT fk_enrollment_class FOREIGN KEY (class_id) REFERENCES CLASS(class_id),
 CONSTRAINT uq_enrollment_student_class UNIQUE (student_id, class_id),
 CONSTRAINT ck_enrollment_status CHECK (status IN ('ACTIVE','DROPPED','COMPLETED'))
);
DESCRIBE ENROLLMENT;

6 — VERIFY: Jangan Berhenti pada “Table Created”

SELECT table_name
FROM user_tables
WHERE table_name IN ('STUDENT','LECTURER','COURSE','SEMESTER','CLASS','ENROLLMENT')
ORDER BY table_name;
SELECT table_name, constraint_name, constraint_type, status
FROM user_constraints
WHERE table_name IN ('STUDENT','LECTURER','COURSE','SEMESTER','CLASS','ENROLLMENT')
ORDER BY table_name, constraint_type;

Untuk melihat kolom yang terlibat pada setiap constraint:

SELECT uc.table_name,
       uc.constraint_name,
       uc.constraint_type,
       ucc.column_name,
       uc.status
FROM user_constraints uc
JOIN user_cons_columns ucc
  ON uc.constraint_name = ucc.constraint_name
 AND uc.owner = ucc.owner
WHERE uc.table_name IN (
 'STUDENT','LECTURER','COURSE',
 'SEMESTER','CLASS','ENROLLMENT'
)
ORDER BY uc.table_name, uc.constraint_name, ucc.position;

P=PK, R=referential/FK, U=unique, C=check-related constraint.
